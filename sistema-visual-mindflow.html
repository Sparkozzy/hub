Diagnóstico

O Problema que
Este Documento Resolve

Os slides gerados pelo agente anterior tinham tipografia correta e cores corretas. Mas eram texto sobre fundo. Isso não é design visual — é diagramação. Este documento resolve o problema na raiz.

O corpus de 30 exemplos de referência da Mindflow — Pereira & Associados, Neobank, CIT Transporte, Canlar, SmartCare e outros — tem uma característica que os slides gerados não têm: elementos visuais com peso físico no frame.

O que os slides gerados tinham

Tipografia sobre gradiente escuro. Hierarquia de tamanho de texto. Cores corretas. Espaço negativo. Zero elementos visuais além de texto.

O que o corpus de referência tem

Fotos de pessoas em zonas definidas. Objetos físicos sangrando para fora do frame. Device mockups como âncoras visuais. Formas geométricas com volume. Múltiplos planos de profundidade. Splits físicos do espaço.

⛔
A Causa Raiz

Um agente sem especificação de assets e composição vai sempre produzir texto diagramado. Ele conhece tipografia. Não conhece composição visual. Este documento é a especificação de composição que faltava.

Este documento especifica o como executável — valores numéricos, estruturas de zonas, tratamentos de assets, gramática de composição. Os dois documentos são complementares. Seção 1 · Frame Zones

O Frame Como
Sistema de Zonas

O frame de 1080×1350px não é uma tela em branco. É um sistema de 6 zonas com função, posição e regras de ocupação definidas. Um agente não toma decisões de onde colocar elementos — ele escolhe qual elemento vai em qual zona.

1.1 Especificação das Zonas

◈
Regra de Zona Única

Um elemento pode FISICAMENTE ocupar múltiplas zonas (um número gigante que começa na zona ÂNCORA e vaza para fora do frame). Mas sua ÂNCORA LÓGICA — o centro visual do elemento — deve estar em uma única zona. Isso determina qual zona "possui" o elemento.

Seção 2 · Layer System

O Sistema de
5 Camadas

Todo post Mindflow é composto de no mínimo 2 e no máximo 5 camadas sobrepostas. Cada camada tem uma função, um z-index, e regras de conteúdo. A profundidade de camadas é o que separa composição visual de texto diagramado.

2.1 As 5 Camadas

L0 · FUNDO
Background
A cor ou gradiente base do slide. Define a temperatura do post. Nunca tem conteúdo — apenas cor ou gradiente de cor. z-index: 0.
z: 0
L1 · TEXTURA
Textura / Elemento de Fundo
Texto-textura gigante, forma geométrica de fundo, padrão sutil. Opacidade 6–15%. Não deve ser lido como conteúdo — é forma. z-index: 1.
z: 1
L2 · ESTRUTURA
Elementos Estruturais
Blocos de cor sólida (split), formas geométricas com peso (retângulos, circles), fotos full-bleed com overlay. Define a divisão física do frame. z-index: 2.
z: 2
L3 · ÂNCORA
Elemento Âncora Visual
O elemento dominante: foto de pessoa cut-out, objeto 3D, número gigante, device mockup. Pode ultrapassar as bordas das camadas inferiores. z-index: 3.
z: 3
L4 · CONTEÚDO
Conteúdo Tipográfico
Todo texto: headline, body, tags, chips, containers de texto, logo, handle. Sempre sobre todas as outras camadas. z-index: 4.
z: 4

2.2 Combinações Mínimas por Tipo de Post

Tipo de PostCamadas obrigatóriasCamadas opcionaisMínimo de camadas
Texto puroL0 + L4L12 (mas evitar — é o padrão fraco)
Dado numéricoL0 + L3 (número) + L4L1 (textura), L2 (separador)3
Com foto de pessoaL0 + L2 (split ou overlay) + L3 (foto) + L4L1 (textura)4
Com objeto/asset 3DL0 + L3 (objeto) + L4L1 (textura), L2 (forma)3

⚠
O Post de 2 Camadas é a Armadilha

L0 + L4 (fundo + texto) é a combinação mínima — e é o que o agente anterior produziu em todos os 5 slides. Um post com apenas 2 camadas é texto diagramado, não composição visual. A menos que o conteúdo seja excepcionalmente forte (uma citação de altíssimo impacto ou um slide de transição), sempre use mínimo 3 camadas.

Seção 4 · Asset System

8 Tipos de Asset —
Tratamento Completo

Um asset visual não é uma imagem jogada no frame. É um elemento com tipo, zona, tratamento de renderização, e regras de posicionamento específicas. Um agente não "adiciona uma foto" — ele aplica o asset correto com o tratamento correto na zona correta.

◈
Regra de Asset

Todo post Mindflow deve ter no mínimo 1 asset visual na camada L2 ou L3 (além do texto na L4). Um post sem nenhum asset visual é texto diagramado — não design de carrossel. A única exceção é o slide de argumento puro (máx 1 por carrossel) e o slide CTA final.

✓ USE
ASSET-01
Foto de Pessoa
Pessoa real do ICP ou equipe Mindflow. Nunca stock genérico de banco de imagens.
✓ USE
ASSET-02
Device Mockup
iPhone ou Android com screenshot da interface do agente Mindflow dentro.
✓ USE
ASSET-03
Screenshot de Chat
Captura de tela de conversa real do agente — com balões de mensagem, timestamps, métricas.
✓ USE
ASSET-04

Ícone vetorial de alta qualidade representando o conceito (waveform, seta, ícone de chat).
✓ USE
ASSET-05

Círculo, retângulo, linha — criada em CSS/SVG. Elemento estrutural puro sem conteúdo.
✓ USE
ASSET-06
Número/Dado como Objeto
O próprio número tratado como objeto visual na L3 — fonte gigante, cor de accent, z-index 3.
✗ PROIBIDO

Emojis 3D flutuantes, ícones 3D de banco de imagens, elementos decorativos sem função.
✗ PROIBIDO

Fotos de banco de imagens de "executivo sorrindo", "aperto de mão", "equipe em reunião".
✓ USE

Gráfico de linha, barra ou pizza criado em CSS/SVG puro — sem bibliotecas externas.

4.1 Tratamentos de Foto de Pessoa (ASSET-01)

Uma foto de pessoa pode receber 4 tratamentos diferentes. O agente escolhe o tratamento baseado no layout selecionado:

TratamentoDescrição técnicaQuando usarCódigo CSS
CUT-OUT Pessoa sem fundo, posicionada sobre o background do slide. Borda natural da pessoa visível. Layout Split, layout com objeto flutuante. Pessoa parece "estar no post". background: transparent; object-fit: contain;
SPLIT-ZONE Foto ocupa metade do frame (L2 estrutural). Sem recorte — foto full dentro da sua zona. Layout A2-Split. A foto está contida dentro da sua zona, não flutua. width: 45%; height: 100%; object-fit: cover; object-position: top center;
FULL-BLEED + OVERLAY Foto ocupa o frame inteiro como fundo (L2). Overlay escuro 40–55% por cima. Texto na L4 sobre o overlay. Posts de storytelling / case. Foto tem peso emocional mas texto precisa ser legível. width: 100%; height: 60%; object-fit: cover; + ::after { background: rgba(0,0,0,0.45); }
THUMBNAIL Foto pequena (80–120px) em container circular ou arredondado. Elemento de suporte, não âncora. Posts com citação de cliente, depoimento, "quem somos". width: 96px; height: 96px; border-radius: 50%; object-fit: cover;

4.3 Overflow Intencional — Quando e Como

O "elemento que vaza" (Padrão A1 do DRS) é uma das técnicas mais características dos exemplos de referência. Aqui está a especificação técnica exata:

/* Container pai do slide — muda para overflow: visible nos slides com overflow */
.slide.has-overflow {
  overflow: visible;  /* ATENÇÃO: requer clip externo no Puppeteer */
}

/* Elemento que vaza pela borda direita */
.overflow-right {
  right: -80px;   /* 80px fora do frame pela direita */
  max-width: calc(100% + 80px);
}

/* Elemento que vaza pela borda inferior */
.overflow-bottom {
  bottom: -100px;  /* 100px fora do frame pela inferior */
}

/* Texto vazando pela borda — para números e palavras âncora */
.overflow-text-right {
  left: var(--margin-h);
  white-space: nowrap;
  /* O texto começa na margem esquerda e vai além do frame pela direita */
  /* Sem max-width — deixa vazar naturalmente */
}

/* REGRA: O que fica DENTRO do frame deve ser suficiente para entender o conteúdo */
/* O que vaza é amplificação, não informação essencial */

Seção 6 · Gramática de Harmonia

Como os Elementos
se Relacionam

A harmonia visual não é estética — é o conjunto de relações matemáticas entre elementos. Tamanho relativo, distância, peso visual. Um agente que aplica estas relações produz composições que "parecem certas" sem saber por quê.

6.1 Hierarquia de Peso Visual — Proporções Obrigatórias

O peso visual de um elemento é determinado pela combinação de tamanho, cor, e contraste. As relações abaixo definem a hierarquia mínima que deve existir entre os três níveis de elementos:

RelaçãoProporção mínimaExemplo concretoSe violada
Âncora : Contexto 3:1 em tamanho de fonte Número âncora 140px, headline de contexto 40px Hierarquia plana — dois elementos competem
Âncora : Corpo 6:1 em tamanho de fonte Número âncora 140px, body text 22px O corpo "rouba" atenção da âncora
Headline : Corpo 2:1 em tamanho + diferença de peso (700 vs 400) Headline 52px 700, body 22px 400 Leitura linear — sem ponto focal claro
Cor de accent : Cor neutra Max 15% da área visual em accent 1 palavra em azul em headline de 6 palavras O accent perde força — vira cor do layout, não destaque
Espaço negativo : Conteúdo Min 40% do frame em espaço vazio Conteúdo ocupa no máximo 60% do frame 4:5 Superlotação — ansiedade visual, usuário rola

Seção 8 · Hard Constraints

O Que Nunca
Pode Acontecer

Estas são restrições absolutas. Um agente que viola qualquer uma delas está produzindo output incorreto — independente de qualquer outra decisão ter sido certa. Cada violação tem uma razão técnica específica.

CONSTRAINT-01 — Zero Post de Texto Puro

Nenhum post do carrossel pode ter apenas texto e background como elementos. Todo post (exceto LAYOUT-07 CTA) precisa de mínimo 3 camadas — L0 + pelo menos um elemento em L1 ou L2 + L4. Se não há asset disponível, usar textura tipográfica (L1) como terceira camada mínima.

CONSTRAINT-02 — Zero Background Warm

Nenhum post pode ter background com temperatura quente. Backgrounds proibidos incluem qualquer cor no espectro amarelo-laranja-vermelho-marrom, incluindo: #F0EDE8, #F4F1EA, #FFF8F0, #FFFAF5, e qualquer cor com HSL hue entre 20° e 80° com saturation acima de 15%. Verificação obrigatória: calcular HSL do background antes de usar.

CONSTRAINT-03 — Zero Dois Elementos Âncora

Cada post pode ter exatamente 1 elemento na zona ÂNCORA (L3). Se houver dois candidatos (número grande + foto de pessoa), um deles deve ser reclassificado como suporte ou movido para outro slide. A âncora é o elemento que responde "onde o olho vai em 0,3 segundos" — deve haver uma única resposta certa.

CONSTRAINT-04 — Zero Dois CTAs no Último Slide

O LAYOUT-07 tem exatamente 1 botão de ação. Qualquer combinação de "acesse o link" + "salve esse post" + "nos siga" no mesmo slide é violação. Definir a conversão desejada antes de gerar o slide e construir o slide exclusivamente para ela.

CONSTRAINT-05 — Zero Emoji como Decoração

Nenhum emoji (incluindo versões 3D/rendered) pode ser usado como elemento decorativo ou de preenchimento visual. Emojis podem ser usados APENAS como ícone funcional dentro de chips (✓, →, ⚡) e apenas quando o ícone é SVG ou caractere unicode simples, não imagem 3D renderizada.

CONSTRAINT-06 — Zero Gradiente sobre Gradiente

Um post pode ter no máximo 1 gradiente. Se o background é gradiente, nenhum outro elemento pode ter gradiente (nem texto, nem overlay, nem forma geométrica). Se um overlay é necessário sobre foto, usar rgba sólido, não gradiente. A única exceção: radial-gradient de brilho sutil no background (L0) é permitido se for o único gradiente no post.

CONSTRAINT-07 — Zero Mais de Uma Cor de Accent por Post

Cada post usa exatamente uma cor de accent: blue (#1A56DB) OU mint (#00C9A7) OU amber (#F5A623). Nunca duas ao mesmo tempo no mesmo post. O branco e os tons de cinza/navy são neutros e não contam como accent. A cor de accent pode mudar entre slides do carrossel, mas não dentro do mesmo slide.

CONSTRAINT-08 — Texto Sobre Foto Requer Tratamento

Qualquer texto que apareça sobre uma fotografia precisa de um dos três tratamentos: (1) overlay rgba(0,0,10,0.45) mínimo sobre toda a foto, (2) container de texto com background opaco mínimo 80%, ou (3) texto na zona split (fora da foto, em bloco de cor). Texto branco sobre foto sem tratamento é violação — o contraste mínimo 4.5:1 não é atingível sem tratamento.

CONSTRAINT-09 — Zero Fonte Fora do Sistema

As únicas fontes permitidas são: Syne (display/âncora), DM Sans (corpo/suporte), DM Mono (dados/sistema). Qualquer outra fonte — Montserrat, Inter, Roboto, fontes do sistema — é violação. As três fontes são carregadas do Google Fonts com os pesos especificados nos tokens.

CONSTRAINT-10 — Zero Afirmação Sem Dado Específico

Este é um constraint de conteúdo, não apenas visual. Qualquer afirmação de performance ou resultado precisa de número específico. "Respondemos rapidamente" → violação. "Respondemos em 4 minutos em média" → válido. Se o dado específico não está disponível, a afirmação deve ser reformulada ou removida.

Seção 9 · Protocolo de Execução

Como o Agente
Executa

O protocolo de execução que um agente deve seguir para cada carrossel gerado. Cada step tem uma saída verificável. Um step não pode ser pulado.

9.1 Protocolo de Geração — 8 Steps

1
Identificar o elemento mais forte do conteúdo
Antes de qualquer decisão visual: qual é o dado, número, frase ou conceito mais impactante do conteúdo a ser comunicado? Esse elemento será a âncora do slide principal. Saída: 1 elemento identificado.
2
Montar a estrutura narrativa do carrossel
Definir quantos slides e qual função cada um terá (usando a tabela da Seção 7.2). Saída: lista de slides com função e layout selecionado para cada um.
3
Verificar regras de sequência
Confirmar: (a) sem dois layouts iguais consecutivos, (b) sem warm no background de nenhum slide, (c) CTA é sempre o último slide. Saída: sequência aprovada ou revisada.
4
Selecionar assets para cada slide
Para cada slide: identificar qual asset vai na L3 (âncora visual). Se não há foto/objeto disponível, usar ASSET-06 (número como objeto) ou textura tipográfica na L1. Saída: asset definido por slide.
5
Definir tokens de cor por slide
Para cada slide: background token + cor de accent (apenas 1). Verificar que nenhum background é warm. Saída: tabela de cores por slide.
6
Gerar o HTML+CSS de cada slide
Usando o layout selecionado como template base, preencher: (a) texto âncora na zona correta com tokens de tipografia corretos, (b) assets nas camadas corretas, (c) elementos de sistema (logo, handle, número de slide) em posições fixas. Saída: HTML+CSS por slide.
7
Verificar Hard Constraints
Checklist das 10 constraints (Seção 8) contra cada slide gerado. Qualquer violação: corrigir antes de avançar. Saída: confirmação de que nenhuma constraint foi violada.
8
Teste Final — As 3 Perguntas
Para cada slide: (1) em 0,3 segundos, o olho sabe onde ir? (2) sem ver o logo, parece Mindflow? (3) em miniatura de 50px, o elemento âncora ainda é reconhecível? Se qualquer resposta for "não" ou "não sei" — revisar antes de renderizar.

A Diferença
Um agente sem este documento gera texto diagramado. Com ele, gera composição.

A diferença não está nas cores nem nas fontes — está nas camadas, nos assets, nas zonas e nas relações entre elementos. Este documento especifica tudo isso em valores que um agente pode executar diretamente.

DRS
Design Reasoning System
Por que as decisões existem. Princípios e padrões para raciocinar sobre design.
VCS (ESTE DOC)
Visual Composition System
Como executar. Zonas, camadas, assets, layouts e constraints em valores numéricos.
PRÓXIMO
Component Library
HTML+CSS renderizável por Puppeteer. Templates prontos para cada layout.
